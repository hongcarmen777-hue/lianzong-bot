# 小苹果 🍎｜《离开伊甸以后》恋综群助手

这是“小苹果”的第一版骨架。

它不是“一个 QQ 群对应一个机器人”，而是：

**一个小苹果 → 多个恋综 → 每个恋综多个群 → 每个恋综独立嘉宾、心动信、心愿、NPC 和数据。**

例如《离开伊甸以后》可以同时拥有：

- 主群 / 大群
- 后台群
- 01、02、03……各自的个人群
- 临时小群
- 地点群
- 游戏群
- 复盘群

不同恋综使用不同 `show code`，数据不会混在一起。

## v0.1 已写入的能力

### 多恋综、多群绑定
骰主建立恋综后，可以把不同 QQ 群绑定到同一个恋综项目下，并标注群类型。

### 嘉宾身份
每个恋综可以登记 01、02、03……等嘉宾。玩家可把自己的 QQ 机器人身份登记到对应嘉宾位。

### 心动信
玩家私聊小苹果发送心动信；小苹果记录后，会尝试投递到目标嘉宾绑定的个人群。

### 心愿墙
支持匿名式“挂心愿 / 心愿墙 / 摘心愿”。

### 随机嘉宾
可以从当前恋综的有效嘉宾中随机抽取指定人数。

### 小群成员记录
在已经绑定为“小群”的 QQ 群里记录该小群有哪些嘉宾。

### DeepSeek 问答
普通 @小苹果 或私聊可以调用 DeepSeek。程序规则类结果不会交给 AI 瞎编。

### NPC 模式
骰主可以保存 NPC 人设，并让某个群临时进入该 NPC 的角色模式。退出后恢复小苹果。

### 公告
骰主可尝试向本群、主群、所有个人群或该恋综全部已绑定群发送公告。

> QQ 官方机器人对主动消息有平台频率/额度限制，所以“广播到很多群”最终能发多少，要以你的机器人权限为准。

## 第一次使用的建议顺序

1. 先部署并让小苹果上线。
2. 私聊：`小苹果 认主 <你在环境变量里设置的 CLAIM_TOKEN>`
3. 私聊：`小苹果 新建恋综 eden | 离开伊甸以后`
4. 添加嘉宾，例如：`小苹果 嘉宾添加 eden 01 | 角色名`
5. 把机器人拉进主群，在群里 @小苹果：`绑定 eden 主群`
6. 把机器人拉进 01 个人群，在群里 @小苹果：`绑定 eden 个人群 01`
7. 玩家在自己的个人群或私聊：`登记我 01`
8. 之后即可使用：`心动信 02 内容`、`挂心愿 内容`、`随机嘉宾 2` 等。

发送 `小苹果 帮助` 可查看当前菜单。

## 环境变量

不要把任何密钥写进 GitHub。

CloudBase 中至少配置：

- `QQ_APP_ID`
- `QQ_APP_SECRET`
- `DEEPSEEK_API_KEY`
- `CLAIM_TOKEN`

可选：

- `DEEPSEEK_MODEL=deepseek-flash`
- `PORT=8080`
- `DATABASE_URL`
- `ENABLE_AI_CHAT=true`
- `AI_HISTORY_LIMIT=12`

## 数据库注意

如果暂时不填写 `DATABASE_URL`，程序会使用容器里的 `/tmp/xiaopingguo.db`。

这只适合**第一次跑通功能**。云容器一旦重启、重新部署，SQLite 数据可能丢失。

正式跑恋综之前，应把 `DATABASE_URL` 接到持久化 PostgreSQL / CloudBase SQL。代码已经留好了 PostgreSQL 支持，不需要重写业务逻辑。

## CloudBase 云托管

这个 QQ SDK 需要保持 WebSocket 在线，所以云托管服务应使用**持续运行 / 高可用**，并保持 **1 个实例**；不要让它长期缩容到 0，也不要开多个实例，否则可能产生重复机器人连接。

服务端口使用 `8080`。程序同时启动一个 `/health` 健康检查接口。

## 目前故意没做的部分

v0.1 没有硬做“完整群聊复盘”。官方 QQ 机器人在普通群聊里主要通过 @事件工作，和手册里使用真实 QQ 账号协议、可以看见群内全部消息的民间骰框架不同。因此完整自动戏录需要另想方案，不能假装官方接口能做到。

复杂背包、商城、地点踩点、PVP、游戏插件、最终双选、每日定时流程会在核心架构跑通后继续加。
